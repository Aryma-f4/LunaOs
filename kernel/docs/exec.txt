EXEC - PROCESS EXECUTION
File: kernel/exec.asm
Author: arfy slowy

OVERVIEW
Loads and executes a flat binary userspace process from a VFS file
knot. Creates an isolated address space using a dedicated PML4 table
with ring-3 accessible code and a ring-0-only kernel context stack.
Sets up an iretq frame on the parent task's context stack for ring-3
return. Propagates errors from page operations back to the caller via
the carry flag.

PROCEDURE FLOW

kernel_exec(RCX=name length, RSI=name+args, RDI=VFS knot, R8=args size)

+-------+-------------------------------------------------------------+
| Step  | Operation                                                   |
+-------+-------------------------------------------------------------+
|  1    | rcx = knot.size -> library_page_from_size (r12 = code size) |
|  2    | args size <= 1 page, else error (KERNEL_ERROR_memory_low)    |
|  3    | rcx += 15 -> kernel_page_secure (reserve physical pages)    |
|  4    | kernel_memory_alloc_page + kernel_page_drain (new PML4, r11)|
|  5    | Map the code area at SOFTWARE_BASE_address (user-accessible)|
|  6    | Map the process binary memory map behind the code           |
|      |   (kernel-only), clear it and mark the taken pages          |
|      |   (kernel_memory_secure; r13 = map address)                 |
|  7    | Map the process stack at KERNEL_TASK_STACK_address          |
|      |   (1 page, user), copy the arguments to its top (r14 = RSP)|
|  8    | Map the kernel context stack at                             |
|      |   SOFTWARE_BASE_address - 8 KiB (2 pages, kernel-only)      |
|  9    | kernel_page_merge — copy the kernel PML4 entries            |
| 10    | Build the iretq frame on the parent task context stack:     |
|       |    [RIP]   = SOFTWARE_BASE_address                  (+0x00)|
|       |    [CS]    = KERNEL_STRUCTURE_GDT.cs_ring3 | 0x03    (+0x08)|
|       |    [RFLAGS]= KERNEL_TASK_EFLAGS_default             (+0x10)|
|       |    [RSP]   = r14 (process stack top)               (+0x18)|
|       |    [SS]    = KERNEL_STRUCTURE_GDT.ds_ring3 | 0x03    (+0x20)|
| 11    | Switch CR3, kernel_vfs_file_read into SOFTWARE_BASE_address,|
|       |   restore CR3                                               |
| 12    | kernel_task_add (name from the knot, rbx = task stack)       |
| 13    | Record task memory size and binary memory map pointer        |
| 14    | Release the unused reserved pages                           |
| 15    | Return: RCX = PID, RDI = task structure pointer             |
+-------+-------------------------------------------------------------+

REGISTER SAVE ORDER (push/pop)
  push: rdx, rsi, rbp, r8, r11, r12, r13, r14, rax, rbx, rcx, rdi
  pop:  rdi, rcx, rbx, rax, r14, r13, r12, r11, r8, rbp, rsi, rdx
  Note: results are returned by overwriting the saved slots before the
        pops (PID -> rcx slot, task pointer -> rdi slot, error -> deeper
        preserved slot).

PAGE TABLE HIERARCHY (4-level paging)

                    CR3
                     |
                     v
 [ PML4 Table ] -- 512 entries x 8 bytes = 4K page
   entry[i] --> PDPT physical address + flags
                     |
                     v
 [ PDP Table ]  -- 512 entries x 8 bytes = 4K page
   entry[i] --> PD physical address + flags
                     |
                     v
 [ PD Table ]   -- 512 entries x 2MB pages = 1GB range
   entry[i] --> PT physical address + flags  (4K pages)
   entry[i] --> 2MB page addr + flags        (huge page)
                     |
                     v
 [ PT Table ]   -- 512 entries x 4K pages = 2MB range
   entry[i] --> 4K page physical address + flags

PROCESS VIRTUAL ADDRESS SPACE

0x0000700000000000  SOFTWARE_STACK_pointer
+------------------------------------------+
| Process stack (1 page, args at top) [U]  |  ring-3 RSP starts here
+------------------------------------------+
0x0000100000001000  (behind the code area)
| Process binary memory map      [kernel]  |  1 page, not user-accessible
+------------------------------------------+
0x0000100000000000  SOFTWARE_BASE_address
| Userspace code (from VFS file)   [U RW]  |  ring-3, RIP starts here
+------------------------------------------+

0x00000FFFFFFFE000  SOFTWARE_BASE_address - 8 KiB
+------------------------------------------+
| Kernel context stack (2 pages) [kernel]  |  ring-0 only
+------------------------------------------+

Note: the new PML4 is merged with the kernel's via kernel_page_merge,
so the process sees the kernel mappings alongside its own.

IRETQ FRAME LAYOUT (on the parent task's context stack)

+0x00: RIP     = SOFTWARE_BASE_address
+0x08: CS      = KERNEL_STRUCTURE_GDT.cs_ring3 | 0x03
+0x10: RFLAGS  = KERNEL_TASK_EFLAGS_default
+0x18: RSP     = process stack top (arguments, then their size)
+0x20: SS      = KERNEL_STRUCTURE_GDT.ds_ring3 | 0x03

When the scheduler switches to this task and iretq executes, the CPU
pops these values, entering ring-3 with CS/RPL=3, SS/RPL=3, and starts
executing at SOFTWARE_BASE_address.

CALLING CONVENTION

Inputs:
  RCX - Number of characters in the program name
  RSI - Pointer to the program name together with the arguments
  RDI - Pointer to the VFS knot of the file to load (regular file)
  R8  - Size of the arguments in Bytes (maximum one page)

Outputs:
  CF  = 1 on error (only error: KERNEL_ERROR_memory_low = 0x0001,
        defined in kernel/config.asm)
  RCX - PID of the newly created process, or 0 on failure
  RDI - Pointer to the task structure, or 0 on failure

Error handling: every critical call (page_secure, page_map_logical,
vfs_file_read, task_add) is followed by `jc .error`.

Dependencies:
  library_page_from_size    - Convert byte size to page count
  kernel_page_secure        - Reserve physical pages
  kernel_memory_alloc_page  - Allocate a zeroed PML4 page
  kernel_page_drain         - Zero a page (after allocation)
  kernel_memory_secure      - Mark pages as used in a binary memory map
  kernel_page_map_logical   - Map a virtual address range
  kernel_page_merge         - Copy kernel PML4 entries into new table
  kernel_vfs_file_read      - Read file contents into memory
  kernel_task_add           - Register process with scheduler (name from VFS knot)
